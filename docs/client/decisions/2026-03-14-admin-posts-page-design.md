# Admin Posts Page Design

**Date:** 2026-03-14
**Area:** client
**Issue:** client #45

## Goal

`/dashboard/posts`를 관리자 글 목록 관리 화면으로 구현한다. 관리자는 이 화면에서 글 상태를 필터링하고, 삭제된 글 포함 여부를 전환하며, 목록을 탐색하고, 삭제 또는 복원 액션을 수행할 수 있어야 한다.

## Scope

- 관리자 글 목록 페이지 구성
- 상태 필터 드롭다운
- 삭제된 글 포함 체크박스
- 글 제목, 상태, 가시성, 작성일, 작업 컬럼 테이블
- 클라이언트 상태 기반 페이지네이션
- 삭제/복원 mutation 연동

## Data Strategy

페이지는 `use client` 컴포넌트로 구현한다. 현재 페이지 번호, 상태 필터, 삭제 포함 여부는 클라이언트 상태로 유지하고, 해당 상태를 TanStack Query query key에 반영해 서버에서 페이지 단위 데이터를 다시 가져온다.

이슈 본문의 `클라이언트 페이지네이션`은 브라우저에서 페이지 상태를 제어한다는 의미로 해석한다. 실제 데이터는 관리자 API의 `page`, `limit`, `status`, `includeDeleted` 파라미터를 사용해 서버에서 가져온다. 이 방식은 기존 API 설계와 일치하고 데이터가 많아져도 안정적이다.

## UI Structure

### 1. Header

상단에는 페이지 제목과 설명을 배치하고, 우측에 `새 글 작성` 버튼을 둔다. 버튼은 `/dashboard/posts/new`로 이동한다.

### 2. Filters

필터 영역은 상태 드롭다운과 `삭제된 글 포함` 체크박스로 구성한다. 필터가 바뀌면 현재 페이지는 1로 초기화한다.

### 3. Table

테이블 컬럼은 제목, 상태, 가시성, 작성일, 작업으로 고정한다.

- 제목은 편집 페이지 링크로 연결한다.
- 상태와 가시성은 시각적으로 구분되는 badge 형태로 표시한다.
- 작성일은 로컬 포맷 문자열로 변환해 노출한다.
- 작업 컬럼은 삭제되지 않은 글에는 `삭제`, 삭제된 글에는 `복원` 버튼을 제공한다.

### 4. Pagination

목록 아래에는 이전/다음 또는 페이지 번호 기반 탐색 UI를 둔다. 페이지 이동은 클라이언트 상태를 갱신하고, 그 상태에 따라 새 데이터를 요청한다.

## Error Handling

- 목록 조회 실패 시 테이블 영역에 오류 메시지와 재시도 액션을 표시한다.
- 삭제/복원 mutation 실패 시 버튼 인접 영역 또는 상단에 간단한 실패 메시지를 표시한다.
- mutation 성공 후에는 현재 query를 무효화해 목록을 다시 가져온다.

## Architecture Notes

- 라우트 파일은 `src/app/dashboard/posts/page.tsx`다.
- API 호출과 타입은 `entities/post` 계층을 재사용한다.
- 페이지 전용 UI가 커지면 `widgets` 또는 `features`로 분리할 수 있지만, 이번 범위에서는 단일 페이지 내부 보조 컴포넌트로 시작해도 충분하다.
- FSD import 방향 `app -> widgets -> features -> entities -> shared`를 유지한다.
